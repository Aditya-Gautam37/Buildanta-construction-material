# Testing and definition of done

A feature is done when requirements and acceptance criteria pass; mobile behavior and all UI states exist; client and server validation are present; authentication and authorization are enforced; errors are clear; automated tests, types, lint, and build pass; documentation is current; and the feature works in staging.

Pre-launch testing covers authentication/logout, every role, product editing, search/filtering, quote submission, inventory updates, mobile/desktop layouts, major browsers, accessibility, SEO, error and empty states, slow networks, backup restoration, monitoring, and alert delivery. Run a limited real-user beta before public launch.

The repository test suite verifies the reference homepage structure, required routes and durable D1/R2 workflow bindings. Browser QA has been performed at desktop and 390px mobile widths for the homepage, mobile menu, product discovery and quote workflow.
